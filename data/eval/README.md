# Eval-набор вопросов (Q-01)

`questions.yaml` — вопросы к агенту по датасетам хакатона и openPsych с
ожидаемым результатом. По нему прогон `scripts/eval.py` (#57, Q-02) считает
долю пройденных вопросов, recall отбора колонок (#108, A-07) и отказы на
«неудобных» вопросах (#41, A-05). `scripts/check_eval_questions.py`
проверяет сам набор: схему записей и эталонные значения на загруженных
таблицах.

## Формат записи

```yaml
- id: sales-02                    # уникальный, [a-z0-9-]
  scenario: 2                     # 1–6 — сценарии из README, 0 — «неудобный»
  dataset: t_01_prodazhi          # имя таблицы в DuckDB после загрузки
  question: "Какой способ оплаты встречается чаще всего?"
  follow_up_of: null              # id предыдущего вопроса той же сессии
  expect:
    tools_any: [group_by, search_categorical_values]
    columns_all: ["Способ оплаты"]
    answer_contains: ["карт"]
    value:
      sql: SELECT "Способ оплаты" FROM t_01_prodazhi GROUP BY 1 ORDER BY count(*) DESC LIMIT 1
      tolerance: 0
    chart_type_any: [bar, kpi, table]
    refusal: false
```

Все ключи обязательны, лишние запрещены. Что значат поля:

| Поле | Значение |
|---|---|
| `dataset` | Имя таблицы, которое даёт `table_name()` загрузчика: `01_Продажи.csv` → `t_01_prodazhi`, `data.csv` → `data`. Сессия прогона создаётся с этой таблицей. |
| `follow_up_of` | Вопрос задаётся в той же сессии сразу после указанного. Предыдущий вопрос стоит в файле выше и задан по той же таблице. У сценария 6 обязателен. |
| `tools_any` | Хотя бы один из этих тулов есть в шагах плана. Имена — тулы, которые видит планировщик (`tool_registry.planner_tools()`). `[]` — не проверяется: обзор таблицы и смена вида графика идут без плана. |
| `columns_all` | Все эти колонки должны попасть в отбор колонок для планировщика. Имена точные, как в DuckDB, с единицами и знаками: `"Количество, шт."`, `"Скидка, %"`. Код без описания пишется полностью: вопрос «Q3» → `Q3A`. |
| `answer_contains` | Каждая подстрока есть в `text.headline` + `details` (без учёта регистра). Числа сюда не пишем: их формат («500 000», «500000») не задан. |
| `value` | Эталон или `null`. `sql` возвращает ровно одну строку с одной колонкой. Ответ верен, если в итоговой таблице (`result_table`) есть ячейка, совпадающая с эталоном. |
| `value.tolerance` | Относительная погрешность для чисел: `|ответ − эталон| ≤ tolerance · |эталон|`; при эталоне 0 — абсолютная. Строки сравниваются точно, без учёта регистра и пробелов по краям, `tolerance` у них 0. |
| `chart_type_any` | Тип графика (`usermeta.chart_type`) — один из списка. Типы — `CHART_TYPES` из `vega_spec_builder.py`. `[]` — не проверяется. |
| `refusal` | `true` — агент отказывает: событие `refusal` или ответ одним текстом без шагов. Уточнение (`clarification_needed`), в том числе шаблонное «Не удалось подобрать инструменты», отказом не считается. Событие `refusal` появится в #41, до этого такие вопросы не проходят. |
| `dashboard` | необязательный; `true` — в ходе пришло событие `dashboard` (сценарий 5) |

Сравнение эталона с ячейкой — функция `matches()` в
`scripts/check_eval_questions.py`, раннер может взять её оттуда.

Правила, принятые при составлении:

- Допуски: счётчики и ответы-строки — 0; средние — 0,01; суммы, где модель
  может по-разному учесть возвраты, — 0,02.
- Эталон — величина, которая окажется в итоговой таблице при разумном
  решении. Поэтому для «сезонных» вопросов в тексте сказано «по месяцам
  года, все годы вместе», а эталон — значение пикового месяца; для
  дашбордов — число записей в 4-м квартале 2025 года.
- `columns_all` — колонки, на которые обязан опереться правильный ответ.
  `[]` — только когда ответ не опирается ни на одну колонку: обзор всей
  таблицы (`psych-01`), вопрос вне данных, бессмыслица, несуществующий код
  (`psych-nocolumn`). В recall отбора такие вопросы не входят. У отказов
  с упоминанием настоящей колонки («удали все возвраты») она указана.
- Сценарий 1 частью идёт обзором таблицы без плана (`is_overview_question`:
  «Что передо мной?», «За какой период собраны данные и сколько всего
  записей?»): у таких вопросов `tools_any: []`, график `table`, в
  `columns_all` — колонка даты, по которой называется период.
- Сценарий 5 дополнительно проверяется событием `dashboard`: у каждого
  его вопроса `dashboard: true`.
- Сценарий 6: просьбы сменить вид («в виде таблицы», «столбчатой
  диаграммой») идут через `_morph` без плана (`tools_any: []`). У «Покажи
  это в другом виде» тип заранее не известен (`chart_type_any: []`):
  раннеру стоит проверять, что тип отличается от прошлого графика.
- Колонки openPsych сейчас загружаются как VARCHAR (#103), после D-08
  станут числами. Эталоны по ним пишутся через `TRY_CAST(… AS DOUBLE)` и
  верны в обоих случаях: повторный заголовок и литералы `NULL` дают NULL.
  Строкой сравнивается только `country = 'NA'` — это и проверяется.

```bash

```

## Проверка эталонов

```bash
python scripts/check_eval_questions.py                  # только схема
python scripts/check_eval_questions.py --db backend/storage/duckdb/main.duckdb
```

Без `--db` скрипт проверяет схему: ключи и типы полей, уникальность `id`,
сценарий 0–6, имена тулов и типов графиков, ссылки `follow_up_of` (вопрос
выше, та же таблица), охват (по 5 вопросов на 5 таблицах в сценариях 1–6,
5 отказов), и печатает сводку. С `--db` он открывает базу только на чтение
(лимит памяти 1 ГБ), сверяет `columns_all` с колонками таблицы и выполняет
каждый `value.sql`, печатая эталон и время. Код выхода 1 — есть проблемы.
Схема проверяется и в `backend/tests/unit/test_eval_questions.py` без
датасетов.

Прогон 2026-10-25 (DuckDB 1.5.6, все 10 таблиц): 51 вопрос, 35 эталонов
выполнены, у 16 `value: null`, проблем нет. Каждый эталон сверен вручную:
например, у `sales-03` чистые продажи в декабре — 181 315 шт., с возвратами
180 067 (в пределах 0,02); у `ads-03` Telegram опережает партнёрские
площадки (1,741 против 1,704).

## Как добавить вопрос

1. Выберите сценарий и таблицу; `id` — `<таблица>-<номер или суть>`.
2. Посчитайте эталон в DuckDB так, чтобы запрос вернул одно значение,
   которое появится в итоговой таблице агента. Если такого нет (график,
   дашборд без числа, открытый вопрос) — `value: null`.
3. Запишите в `columns_all` все колонки, без которых ответ неверен, точными
   именами.
4. Запустите `scripts/check_eval_questions.py --db …` и тесты
   `tests/unit/test_eval_questions.py`.
