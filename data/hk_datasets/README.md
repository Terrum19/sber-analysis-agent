# Датасеты хакатона (HK_Datasets)

Девять CSV кейса «AI-Native BI Система»: продажи, техподдержка, задачи
команд, доставка, события приложения, рекламные кампании, заявки на
закупку, фоновые задания, лекарственные препараты. Описание колонок — в
README репозитория с данными.

Скачать и загрузить в DuckDB:

```bash
make hk-data
```

Если в папке не ровно 9 CSV или нет `description.md`, команда клонирует
https://gitverse.ru/kban/HK_Datasets целиком (≈1,5 ГБ, около 3 минут) и
докопирует недостающие файлы, уже лежащие не перезаписывает; README
репозитория с описанием колонок ложится в `description.md`. Затем
`scripts/load_hk_datasets.py --no-llm` загружает каждый файл в
`main.duckdb`, сразу строит профиль и паспорт таблицы и печатает таблицу
результатов. Без `--no-llm` скрипт ещё переносит из `description.md` в
паспорт названия и описания колонок (нужна LLM). Перед запуском остановите backend: DuckDB допускает
только одного писателя.

Вручную:

```bash
git clone https://gitverse.ru/kban/HK_Datasets /tmp/HK_Datasets
cp /tmp/HK_Datasets/*.csv data/hk_datasets/
cp /tmp/HK_Datasets/README.md data/hk_datasets/description.md
python scripts/load_hk_datasets.py --no-llm
```

Формат: UTF-8, разделитель `;`, десятичная запятая. В DuckDB:

```sql
SELECT * FROM read_csv('data/hk_datasets/09_Лекарственные_препараты.csv',
                       delim = ';', decimal_separator = ',', header = true);
```

Вместе файлы занимают около 1,5 ГБ, отдельные — больше 200 МБ (лимит
GitHub — 100 МБ), поэтому всё содержимое папки, кроме этого README,
в `.gitignore` и в git не попадает.

## Результаты загрузки

Прогон 2026-10-20 в режиме с LLM: Apple M4 (10 ядер), 16 ГБ RAM,
macOS 26.6, DuckDB 1.5.6, модель `qwen2.5:7b` в Ollama 0.33.2.

```bash
LLM_MODEL=qwen2.5:7b python scripts/load_hk_datasets.py
```

Все 9 файлов загружаются строгим разбором, число строк и колонок
совпадает с описанием в README репозитория с данными. «Профиль, с»
здесь включает описания колонок от LLM, весь прогон — 9 минут.
Прогон снят до того, как энричер перестал генерировать описания и стал
только переносить их из `description.md`; сейчас скрипт печатает
колонки «Загрузка и профиль, с» и «Описание, с».
`make hk-data` запускает скрипт с `--no-llm`: профиль без LLM занимает
меньше секунды на таблицу, а все 9 датасетов загружаются ≈15 с.

Найденные проблемы:

- `ID_Аптеки` и `ID_Лекарства` в `09_Лекарственные_препараты.csv`
  загружаются как `BIGINT`, по описанию датасета это текстовые
  идентификаторы. Остальные 143 колонки совпадают с описанием по типу.
- LLM описала 5 колонок из 145: в промпте у колонки передаётся
  `"description": null`, и модель возвращает null.
- Невалидный JSON от LLM отбрасывает всю пачку: в `01_Продажи.csv`
  так потеряны все 22 колонки.
- `make dev` запускает backend из `backend/`, и относительный
  `DUCKDB_PATH` указывает на `backend/backend/storage/duckdb/main.duckdb`,
  а не на базу, которую заполняет `make hk-data`.
