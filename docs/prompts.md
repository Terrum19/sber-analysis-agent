# Промпты платформы

Все промпты лежат в `backend/app/core/llm/prompts/` и версионируются как код.

| Файл | Назначение | Сценарий кейса |
|---|---|---|
| `system_analyst.py` | системная роль: аналитик + список тулов + правила | все |
| `schema_describe.py` | «Что передо мной?» — описание данных простым языком | №1 |
| `alias_gen.py` | пачка колонок -> JSON `{columns: [{column, description?, aliases[]}]}`: до 4 алиасов на колонку и описания там, где их нет (+ бизнес-словарь) | №1-2 |
| `description_compress.py` | длинное описание колонки из источника -> одно предложение не длиннее `ENRICH_DESCRIPTION_MAX_CHARS` с терминами, единицами и кодами | №1-2 |
| `step_planner.py` | вопрос -> список ResearchStep | №2-6 |
| `insight_summary.py` | результат -> «узнали то, узнать невозможно» | №2-6 |
| `chart_selector.py` | выбор типа визуализации под вопрос | №4 |

## Правила работы с промптами

1. Промпт меняется только в своём файле — не захардкожен в оркестраторе.
2. Structured output валидируется по Pydantic-схеме (Instructor).
3. Невалидный вывод LLM -> robust-парсер (`core/agent/parser.py`) -> ретрай.
