# Промпты платформы

Все промпты лежат в `backend/app/core/llm/prompts/` и версионируются как код.

| Файл | Назначение | Сценарий кейса |
|---|---|---|
| `system_analyst.py` | системная роль: аналитик + список тулов + правила | все |
| `schema_describe.py` | «Что передо мной?» — описание данных простым языком; с `SCHEMA_DESCRIBE_JSON` — JSON `{display_name, summary}` с названием таблицы для пользователя (`core/data/overview.py`, кеш в паспорте) | №1 |
| `column_extract.py` | документ-описание таблицы + пачка колонок -> JSON `{columns: [{column, title, description}]}`: только то, что написано в документе, иначе `null` | №1-2 |
| `step_planner.py` | вопрос -> список ResearchStep; для вопроса про дашборд — `DASHBOARD_PLAN` с плитками шаблона или просьбой составить 3–6 плиток; `MEMORIES` — воспоминания сессии, `PAST_TURNS` + `OLDER_TURNS` — последние ходы и указание на `read_history`, поле `remember` — просьба запомнить (#197); `CLARIFICATIONS` — ответы на уточняющие вопросы глубокого исследования (A-28) | №2-6 |
| `insight_summary.py` | результат -> «узнали то, узнать невозможно»; `INSIGHT_SUPPORTING` — сопутствующие результаты, только когда они есть; `P_VALUE_RULE` — порог 0,05, только если в результате или сопутствующих таблицах есть колонка `p_value` (#216); `INSIGHT_MEMORIES` — воспоминания сессии (#197); `INSIGHT_STRUCTURE` / `INSIGHT_STREAM_STRUCTURE` — формат ответа: поля схемы `Insight` или Markdown для стрима (первая строка с ключевыми числами, `- ` пункты, «Ограничения:»; при `INSIGHT_STREAM` первая строка проверяется H-Q3 до показа); `INSIGHT_CLARIFICATIONS` + `INSIGHT_GOAL` — уточнения и цель пользователя, на которую отвечает вывод (A-28); `TILE_INSIGHT` — вывод в 1–2 предложения к плитке дашборда | №2-6 |
| `clarify.py` | глубокое исследование (A-28): вопрос, таблица, прошлые ходы и воспоминания -> `{enough_info, questions}`, 3–4 вопроса по осям (цель, метрика, период, разрез, фильтр, форма ответа) с вариантами из данных; `CLARIFY_RETRY` — причина отказа при повторе | №2-6 |
| `chart_selector.py` | график ответа: таблица шага, вид и колонки осей (`ANSWER_CHART`); общий список видов `CHART_KINDS` | №4 |
| `quality_rules.py` | при `AGENT_QUALITY_FIXES`: подсказки к тулам, правила планировщика (в том числе «NULL в долях и `CASE WHEN` — не 0»), факты и проверка чисел для инсайта (опора — весь промпт, «тыс/млн/млрд» сверяются с делёнными числами, #216), правило ответа для тренда, сезонности и разложения (`RESULT_SHAPES`), рамка прошлых шагов; `NULLS_HINT`, `TIE_HINT`, `PARTIAL_HINT` — подсказки инсайту, только когда сработал факт о пропусках, ничьей на вершине или неполном периоде (#216) | №2-6 |
| `structured_repair.py` | переспрос, когда ответ не прошёл JSON-схему | все |

## Правила работы с промптами

1. Промпт меняется только в своём файле — не захардкожен в оркестраторе.
2. Structured output валидируется по Pydantic-схеме (Instructor).
3. Невалидный вывод LLM -> robust-парсер (`core/agent/parser.py`) -> ретрай.
