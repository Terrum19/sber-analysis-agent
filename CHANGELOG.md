## Ещё не в `dev` (ждут ревью)

### Фронтенд: чат и подключение данных (#13)

- Чат больше не обрывает SSE-поток сразу после отправки: ответ приходит
  по частям и сразу отображается. Остановить ответ можно кнопкой «Стоп».
- В чате появились кнопки «Загрузить CSV» и «Подключить БД». В форме
  БД есть и ClickHouse, но на бэкенде пока работает только PostgreSQL.
- Фронтенд в Docker Compose проксирует `/api` в контейнер `backend:8000`,
  а не в `localhost`. Адрес задаётся `NEXT_PUBLIC_API_URL` при сборке образа.
- Бэкенд запрещает прокси сжимать и копить поток чата: без этого
  браузер получал весь ответ разом в конце.

### Визуализации (#14)

- `build_vega_spec()` строит готовые Vega-Lite v5 спецификации с данными
  и осями для графиков bar, line, area, scatter, histogram, box, heatmap и
  для таблицы. Подписи осей на русском берутся из паспорта данных.
- Просьба «покажи в другом виде» или «сделай таблицей» перестраивает
  последний график из кэша: SQL заново не выполняется, LLM не вызывается.
- `ChartRenderer` рисует Vega-Lite, ECharts и таблицы.

## В `dev`

### Загрузка CSV (#15, #21)

- Сырые CSV загружаются без предобработки: кодировка (UTF-8, UTF-16,
  cp1251), разделитель, русские числа (`1 234,56`) и даты определяются
  автоматически. «Рваные» строки и ошибки формата не роняют загрузку.
- `POST /api/datasources/csv` принимает несколько файлов (поле `files`),
  размер ограничен `CSV_MAX_UPLOAD_MB` (1 ГБ). Если хотя бы один файл не
  загрузился, не подключается ни один.
- CSV один раз копируется в таблицу DuckDB: запросы и профилирование по
  ней работают в 15–30 раз быстрее, чем по самому файлу. Все 9 датасетов
  хакатона загружаются примерно за 50 секунд.

### Датасеты хакатона (#17)

- Числовые коды (`ID_Аптеки`, номера чеков и т. п.) считаются категориями,
  а не показателями: среднее и выбросы по ним не считаются, и LLM получает
  указание не суммировать их. Коды узнаются по имени колонки и по
  значениям, поэтому правило работает и на незнакомых датасетах.
- Датасеты хакатона хранятся в `data/hk_datasets/` и не попадают в git
  (файлы больше лимита GitHub). Откуда их взять — в README этой папки.

### Паспорт данных (#11)

- Профиль таблицы стал полным паспортом данных: пропуски, уникальные
  значения, частые значения, квантили, выбросы и замечания о качестве.
  Таблица в 1 млн строк и 50 колонок должна профилироваться не дольше
  10 секунд, это проверяет бенчмарк.
- Описание данных для LLM включает блок «Качество данных». При выборе
  колонок под вопрос учитывается их тип.

### Подключение PostgreSQL (#10)

- `POST /api/datasources/db` подключает схему PostgreSQL к DuckDB только
  для чтения, данные не копируются. Пароль в логах и ответах скрывается.
- Для проверок есть сервисы PostgreSQL и ClickHouse в Docker Compose и
  интеграционные тесты. Сам коннектор ClickHouse ещё не написан.

### CI/CD и инфраструктура (#10)

- GitHub Actions: проверки бэкенда (ruff, юнит- и интеграционные тесты,
  100% покрытия для ключевых модулей) и фронтенда (lint, типы, сборка).
- Проверка, что `docker compose up` поднимается; сборка релиза с
  офлайн-пакетом Docker-образов для замкнутого контура.
- Автопроверки: правила коммитов (заголовок на английском, описание на
  русском, без комментариев в `.py`), поиск секретов (gitleaks), аудит
  зависимостей (Dependabot, pip-audit), ручной дымовой тест агента на
  локальной LLM (Ollama).
- Фронтенд снова собирается: исправлены ошибки типов, зафиксирован
  `package-lock.json`.
