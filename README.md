# SberAnalyticalAgent

**AI-Native BI-платформа**: аналитик или руководитель задаёт вопрос о данных
обычным языком и получает ответ, график или дашборд — без SQL и без
разработчика. Агент на локальной LLM (Qwen 2.5-Coder через Ollama) планирует
исследование по шагам, считает в DuckDB и пишет Python в WASM-песочнице.
Всё работает в **замкнутом контуре**: данные и модель не покидают машину.

## Быстрый старт

Нужны Docker с плагином `docker compose` и git.

```bash
git clone https://github.com/Terrum19/sber-analysis-agent.git && cd sber-analysis-agent
cp .env.example .env
make up
```

Откройте http://localhost:3000. Первый запуск собирает образы и скачивает
модель (несколько ГБ, время зависит от сети); backend ждёт, пока Ollama не
загрузит модель, поэтому интерфейс появляется не сразу. Повторные запуски берут модель из тома
`ollama-models` и стартуют за секунды.

- **GPU NVIDIA:** `make up-gpu` вместо `make up` (нужен NVIDIA Container Toolkit);
  модель — `LLM_MODEL_GPU` из `.env`.
- **Остановить:** `make down`. Данные (подключённые таблицы, сессии, дашборды)
  лежат в `backend/storage/` и переживают перезапуск.
- **Порты:** интерфейс 3000, API 8000 (документация API — http://localhost:8000/docs),
  Ollama 11434 (`OLLAMA_PORT` в `.env`).

## Требования к железу и выбор модели

<!-- TODO(#58): заменить модели и цифры итогами выбора по eval (docs/reports/llm_choice.md). -->

| Режим | Команда | Модель по умолчанию | Память под модель* | Диск |
|---|---|---|---|---|
| CPU | `make up` | `qwen2.5-coder:7b` (`LLM_MODEL`) | ≈ 6 ГБ RAM | ≈ 5 ГБ |
| GPU NVIDIA | `make up-gpu` | `qwen2.5-coder:14b` (`LLM_MODEL_GPU`) | ≈ 12 ГБ VRAM | ≈ 9 ГБ |

\* Веса модели в 4-битной квантизации плюс кеш контекста на 16 тыс. токенов
(`OLLAMA_CONTEXT_LENGTH`). Ориентировочные оценки, замеры — в отчёте о выборе
модели. Сама платформа (backend, frontend, DuckDB) занимает ещё около 2 ГБ RAM и
4 ГБ диска под образы.

- **Рекомендуется:** 16 ГБ RAM и 4+ ядра для CPU-режима; на CPU ответ занимает
  десятки секунд, на GPU — секунды.
- **Слабая машина:** в `.env` можно поставить `LLM_MODEL=qwen2.5-coder:1.5b`
  (≈ 1 ГБ) — работает быстрее, но планирует заметно хуже.
- **Другая модель:** любая модель из библиотеки Ollama — достаточно поменять
  `LLM_MODEL` в `.env` и выполнить `make up`; она скачается при старте.

## Данные

- **CSV:** кнопка загрузки в интерфейсе. Кодировка (UTF-8 или cp1251),
  разделитель и числа вида «1 234,56» распознаются автоматически; файл до
  1 ГБ (`CSV_MAX_UPLOAD_MB`). К файлу можно приложить описание данных (README,
  словарь колонок) — из него в паспорт таблицы попадут названия и описания колонок.
- **PostgreSQL:** форма подключения в интерфейсе, строка вида
  `postgresql://user:password@host:5432/dbname`. Подключение только на чтение;
  после перезапуска источник восстанавливается сам, пароль берётся из
  `POSTGRES_PASSWORD` в `.env` (на диск он не пишется).

## Сценарии

<!-- TODO(#80): скриншоты в docs/img/ после bug bash (#81). -->

Примеры вопросов — на датасетах хакатона (`01_Продажи.csv`,
`02_Техническая_поддержка.csv`, `04_Доставка.csv`).

1. **Знакомство с данными.** Загрузите `01_Продажи.csv` и спросите
   «Что передо мной?» — описание таблицы, период, ключевые колонки.
2. **Вопросы по содержанию.** «Какие категории товаров продаются чаще всего?»,
   «Какой средний чек в каждом канале продаж?»
3. **Группировки и аномалии.** «Что происходит с продажами каждый декабрь?»,
   «В какие недели обращений в поддержку было аномально много?»
4. **Авто-визуализация.** «Покажи наглядно, как распределены сроки доставки» —
   вид графика подбирается под данные.
5. **Дашборд по запросу.** «Создай дашборд с ежеквартальной статистикой продаж» —
   дашборд сохраняется и открывается позже из списка дашбордов.

## Ограничения

<!-- TODO(#81): сверить список после bug bash. -->

- Один пользователь на экземпляр: авторизации нет, рассчитано на локальный запуск.
- Качество ответов зависит от модели: маленькие модели (1.5b–3b) чаще ошибаются
  в плане и просят уточнения.
- На CPU ответ на сложный вопрос — до минуты и дольше.
- GPU-режим — только NVIDIA (`make up-gpu`); на AMD и Apple модель работает на CPU.
- PostgreSQL: из схемы подключается до 50 таблиц (`POSTGRES_MAX_TABLES`); параметры
  строки подключения кроме хоста, порта, базы и пользователя (например `sslmode`)
  после перезапуска не восстанавливаются.
- Код, который пишет агент, выполняется в WASM-песочнице без сети, с лимитами
  60 с и 2 ГБ на запуск (`WASM_TIMEOUT_S`, `WASM_MEM_MB`).
